Investment OS scores a stock against a rule set, and every rule either
passes, fails, or produces a `Gap`, an honest "couldn't check this,
here's why," never a guess. That third state exists specifically so the
system never fabricates a signal when the data isn't there.

Then the portfolio engine added a fourth thing that looked like a `Gap`
but wasn't one: a rule that's *structurally excluded* for a sector.
Debt-to-equity, for example, doesn't mean the same thing for a bank as it
does for an industrial. So the check is excluded outright for Financial
Services, not run-and-failed, not run-and-gapped. It felt like the same
bucket as `Gap` at first, so that's where it went.

It wasn't the same bucket. The Conviction cap logic checked "are there any
`Gap`s dragging this down," and an excluded rule never produces a `Gap`
object. It just isn't there. So a holding could sail through the
Financial Services check with no debt-to-equity read at all, and nothing
in the pipeline ever registered it as missing information. The bug sat
there until a live pass against a real ticker (`HDFCBANK.NS`) came back
with a Conviction that was obviously too confident for how little the
system actually knew. Fixing it meant giving "structurally excluded" its
own explicit state everywhere in the scoring pipeline, not just closer to
`Gap`. That's more states to carry through the code, but the alternative
was a confidence score that could be wrong in exactly the cases where a
whole category of check was quietly turned off.
